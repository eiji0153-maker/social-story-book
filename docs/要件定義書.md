# SocialStory Book 要件定義書

## 0. ドキュメント情報
- プロダクト名: SocialStory Book（ソーシャルストーリー絵本メーカー）
- バージョン: 1.1（AI自動生成を追加）
- 作成日: 2026-07-05
- 対象読者: 開発担当者 / 特別支援教育の職員（利用者）

> 本書末尾の「追補（v1.1）」に、テーマ入力からの自動生成機能を定義しています。

---

## 1. 背景・目的

### 1.1 背景
特別支援教育の現場では、自閉スペクトラム症などのある子どもが苦手とする
「初めての場面」「暗黙のルール」「感情の切り替え」を、
**ソーシャルストーリー**（具体的な場面をやさしい言葉と絵で説明する手法）で
支援することが多い。

例:
- 「給食が終わったら、自分の食器を棚に戻す」
- 「友達が泣いていたら、声をかける」

現状、こうした教材は職員が手作業（紙・パワーポイント等）で作成しており、
- 作成に時間がかかる
- 個々の子どもに合わせた作り直しが大変
- 柔らかいタッチの挿絵をそろえにくい

という課題がある。

### 1.2 目的
職員が **Webブラウザ上で**、想定した場面を入力し、
**柔らかいタッチのイラスト＋やさしい文章**を組み合わせて
オリジナルの絵本を作り、**PDFとして出力**できるツールを提供する。

### 1.3 利用者・利用環境
- 利用者: 社内（校内・施設内）の職員。ITスキルは初級〜中級を想定。
- 利用環境: 社内PCのモダンブラウザ（Chrome / Edge の最新版）。
- ネットワーク: オフラインでも動作すること（データはブラウザ内に保存）。
- 個人情報: 子どもの情報を扱う可能性があるため、外部サーバーに送信しない（ローカル完結）。

---

## 2. スコープ

### 2.1 MVP（フェーズ1）のスコープ
- ブックの作成・一覧・保存・削除
- 想定場面の入力（タイトル・場面メモ）
- ページの追加・削除・並び替え
- イラストの描画（柔らかいブラシ／色／消しゴム／クリア）
- 画像アップロード
- 各ページの文章入力
- 絵本プレビュー
- PDF出力

### 2.2 スコープ外（フェーズ2以降）
- 音声録音・再生、ふりがな自動付与、テンプレート（フェーズ2）
- 動画埋め込み、AI自動生成、クラウド共有、TTS（フェーズ3）

---

## 3. 用語定義
| 用語 | 定義 |
|------|------|
| ブック | 1つの絵本。複数ページとメタ情報（タイトル・場面）を持つ。 |
| ページ | 絵本の1見開き相当。イラスト1点と文章を持つ。 |
| 柔らかいブラシ | 色鉛筆・クレヨンで描いたような、輪郭がやわらかく半透明で重なる描画。 |
| キャンバス | ページのイラストを描画する領域。 |

---

## 4. 機能要件

### FR-1 ブック管理
- FR-1-1: 新しいブックを作成できる（初期タイトル「あたらしい えほん」）。
- FR-1-2: 作成済みブックの一覧を表示できる（タイトル・更新日時）。
- FR-1-3: 一覧からブックを開いて編集できる。
- FR-1-4: ブックを削除できる（削除前に確認する）。
- FR-1-5: 編集内容はブラウザのlocalStorageに保存され、再訪時に復元される。
- FR-1-6: 保存はユーザー操作（保存ボタン）で明示的に行える。

### FR-2 想定場面の入力
- FR-2-1: ブックのタイトルを入力・編集できる。
- FR-2-2: 想定場面のメモ（例:「給食のかたづけ」）を入力できる。
- FR-2-3: タイトル・場面メモは保存対象である。

### FR-3 ページ管理
- FR-3-1: ページを末尾に追加できる。
- FR-3-2: 任意のページを削除できる（最低1ページは残す）。
- FR-3-3: ページの順序を前後に入れ替えられる。
- FR-3-4: 編集対象ページを選択でき、選択中ページが視覚的に分かる。
- FR-3-5: ページには通し番号が表示される。

### FR-4 イラスト描画
- FR-4-1: マウス／タッチでキャンバスに描画できる。
- FR-4-2: 描画は柔らかいタッチ（半透明で重なるクレヨン/色鉛筆風）である。
- FR-4-3: 色を複数の候補から選択できる。
- FR-4-4: ブラシの太さを変更できる。
- FR-4-5: 消しゴムで一部を消せる。
- FR-4-6: キャンバス全体をクリアできる（確認あり）。
- FR-4-7: 描いた内容はページの画像として保存される。

### FR-5 画像アップロード
- FR-5-1: 画像ファイル（PNG/JPEG）をアップロードして、そのページのイラストにできる。
- FR-5-2: アップロード画像はキャンバスに収まるように表示される。

### FR-6 文章入力
- FR-6-1: 各ページに文章を入力できる。
- FR-6-2: 文章は保存対象で、プレビュー・PDFに反映される。
- FR-6-3: 子どもが読みやすいよう、大きめの文字で表示される。

### FR-7 プレビュー
- FR-7-1: 作成中のブックを絵本形式（イラスト＋文章）でプレビューできる。
- FR-7-2: ページを前後に送れる。
- FR-7-3: 編集画面に戻れる。

### FR-8 PDF出力
- FR-8-1: ブック全ページをPDFとして出力（ダウンロード）できる。
- FR-8-2: PDFには各ページのイラストと文章が含まれる。
- FR-8-3: 日本語の文章が文字化けせず出力される。
- FR-8-4: PDFのファイル名にはブックタイトルを含む。
- FR-8-5: 1ページ = PDF1ページとして出力される。

---

## 5. 非機能要件

### NFR-1 ユーザビリティ
- 職員が説明書なしでも主要操作にたどり着けるUI（大きめのボタン・日本語ラベル）。
- 主要操作（作成→描く→書く→PDF）が同一画面遷移内で完結する。

### NFR-2 パフォーマンス
- 10ページ程度のブックのPDF出力が数秒以内に完了する。
- 描画の追従遅延が体感で気にならない（60fps目安）。

### NFR-3 互換性
- Chrome / Edge 最新版で動作する。

### NFR-4 セキュリティ・プライバシー
- データは外部送信せず、利用PCのブラウザ内（localStorage）に保存する。
- 画像もData URLとしてローカル保存する。

### NFR-5 保守性
- 機能ごとにコンポーネントを分割する。
- 型定義（TypeScript）でデータ構造を明示する。

### NFR-6 テスト容易性
- 主要操作要素に `data-testid` を付与し、E2Eテスト（Playwright）を可能にする。

---

## 6. データ要件

### 6.1 データモデル
```ts
type Page = {
  id: string;          // 一意ID
  text: string;        // ページ本文
  imageDataUrl: string | null; // イラスト（PNG Data URL）
};

type Book = {
  id: string;          // 一意ID
  title: string;       // ブックタイトル
  scene: string;       // 想定場面メモ
  pages: Page[];       // 1件以上
  createdAt: number;   // 作成日時(epoch ms)
  updatedAt: number;   // 更新日時(epoch ms)
};
```

### 6.2 保存先
- キー: `socialstory.books`（localStorage）
- 値: `Book[]` の JSON 文字列

---

## 7. 画面要件
| 画面 | 内容 |
|------|------|
| ブック一覧 | ブックの一覧表示、新規作成、開く、削除。 |
| エディタ | タイトル/場面入力、ページ一覧、キャンバス、文章入力、プレビュー/PDF/保存。 |
| プレビュー | 絵本形式表示、ページ送り、戻る。 |

---

## 8. 制約・前提
- MVPは単一利用者・単一PC内での利用を前提とする（共有機能なし）。
- localStorageの容量上限（概ね5MB）を超える大量画像は想定しない。
- 動画・音声・AI生成はMVPスコープ外。

---

## 9. 受け入れ基準（MVP完了条件）
1. 新規ブックを作り、タイトルと場面を入力して保存できる。
2. ページを追加・削除・並び替えできる。
3. 柔らかいタッチで絵を描き、色・太さ変更・消しゴム・クリアができる。
4. 画像をアップロードしてページのイラストにできる。
5. 各ページに文章を入力できる。
6. プレビューで絵本形式に表示され、ページ送りできる。
7. PDFを出力でき、日本語が文字化けせず、全ページ含まれる。
8. 再読み込み後も保存済みブックが復元される。

# 追補（v1.1）: テーマからのAI自動生成

## A-1. 目的・方針
- 職員が「タイトル／伝えたいテーマ」を入力するだけで、各ページの**文章とイラストを自動生成**し、絵本のたたき台を作れるようにする。
- 生成後は既存の編集画面（v1.0）で手直しし、プレビュー・PDF出力できる。
- **バックエンドは持たず**、GitHub Pages のまま動作する（各職員が自分のAPIキーを設定）。

## A-2. 生成方式（決定事項）
| 対象 | 方式 | 補足 |
|------|------|------|
| 文章 | AI生成（Gemini） | 常に Gemini で生成。APIキー必須。 |
| イラスト | AI画像生成（Gemini） | 常に Gemini で色鉛筆・クレヨン風の絵本タッチを生成。個別ページの生成失敗時のみ、絵本を壊さないよう代替イラストに切替。 |
| 個人情報 | 入力しない運用 | 子どもの名前等は入力しない前提でクラウドAIを利用可とする。 |
| キー・費用 | 各職員が各自設定 | APIキーは各端末の localStorage にのみ保存。共有サーバーは持たない。 |

- 採用AI: **Google Gemini API**（文章・画像の両方に対応、ブラウザから直接呼び出し、キー1つで完結）。
- APIキーが未設定の場合、自動生成は実行できない（設定へ誘導）。「白紙から作る」手動作成は引き続き利用可能。
- イラストの画風指定: 色鉛筆・クレヨンで手描きしたような、パステル調でやわらかい絵本の挿絵。文字・枠・吹き出しは入れない。

## A-3. 機能要件（追加）
### FR-9 AI設定
- FR-9-1: APIキー・文章モデル名・画像モデル名・既定ページ数・AI使用可否（文章/画像）を設定できる。
- FR-9-2: 設定は localStorage に保存され、外部送信されない（AI呼び出し時を除く）。
- FR-9-3: 「キーを確認」で疎通テストができ、成否を表示する。

### FR-10 テーマからの自動生成
- FR-10-1: テーマ（伝えたい場面）とページ数を入力して絵本を生成できる。
- FR-10-2: 生成の進捗（文章→各ページのイラスト）が表示される。
- FR-10-3: キー設定時は文章・イラストをAIで生成する。
- FR-10-4: キー未設定時はテンプレート文章＋代替イラストで生成する（アプリは必ず完成させる）。
- FR-10-5: AI生成に失敗した場合はテンプレート/代替へ自動フォールバックし、理由を通知する。
- FR-10-6: 生成結果はブックとして保存され、編集画面が開く。
- FR-10-7: 個人情報を入力しないよう画面上で注意喚起する。

### FR-11 イラストの再生成
- FR-11-1: 編集画面で、選択中ページのイラストをAI（またはキー未設定時は代替）で作り直せる。

## A-4. 非機能・制約（追加）
- NFR-A1: APIキーは端末内保存のみ。公開リポジトリのコードにキーを含めない。
- NFR-A2: モデル名は将来変更に備え、設定画面から変更可能とする。
- NFR-A3: プライバシー: テーマ等の入力テキストと生成要求は、AI利用時のみ Google (Gemini) に送信される。子どもの個人情報は入力しない運用とする。
- 制約: 画像生成は Anthropic Claude では不可のため、画像は Gemini を用いる。

## A-5. データ要件（追加）
```ts
type AiSettings = {
  apiKey: string;        // Gemini APIキー（端末内のみ）
  textModel: string;     // 文章モデル（既定: gemini-2.5-flash）
  imageModel: string;    // 画像モデル（既定: gemini-2.5-flash-image-preview）
  pageCount: number;     // 生成ページ数
  useAiText: boolean;    // 文章をAIで生成
  useAiImages: boolean;  // イラストをAIで生成
};
```
- 保存キー: `socialstory.ai.settings`（localStorage）
- Page 型に `illustrationPrompt?`（イラスト再生成用の説明）を追加。

## A-6. 受け入れ基準（追加）
1. AI設定でキーを保存・確認できる。
2. キー未設定でも、テーマ入力→テンプレート文章＋代替イラストで絵本が完成する。
3. キー設定時、テーマ入力→AIで文章・イラストが生成される。
4. 生成失敗時に自動フォールバックし、通知される。
5. 生成後、編集画面で手直し→プレビュー→PDF出力できる。
